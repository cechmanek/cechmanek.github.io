STEP BY STEP GUIDE
1. Read the PROJECT.md file to fully understand major goals of the software project.
2. If a TASKS.md file does not exist in the project root directory then create one that contains a numbered list of software classes that must be writtin in order for the overall project to be completed. Tasks should be listed in sequential order such that tasks at the top of the list do not depend on subsequent tasks.
3. Read TASKS.md and starting from the first task note marked as "TODO <task description> TODO", complete the task. After completeing the task, edit TASKS.md and annotad the task as "DONE <task description> DONE"
4. If necessary, edit subsequent tasks or append to TASKS.md
5. Return to step 3 and repeat until all taks in TASKS.md are marked as DONE.


BEST PRACTICES
- Develop this project using Python3
- Strongly prefer mainstream packages over lesser known packages
- Prefer building flatter project directory hierarchies over deep ones
- Use descriptive variable names and avoid abbreviations
- Use object oriented Python, while preferring that class methods be stateles when reasonable
- Use iterative development. Write the minimal amout of code, while still maintaining high readability and descriptive coding style
- Add a git commit with messsage after each new Python class is created
- Add a git commit with message after each change to an existing class
- Prefer smaller and more frequent git commits and group them such that changes to unrelated files are in separate commits
